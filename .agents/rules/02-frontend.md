# Frontend Architecture & Standards (`client-web/`)

Stack (package manager: **pnpm**): React 19, Vite, TypeScript, Tailwind 3 (`darkMode: ["class"]`), Shadcn UI (style `default`, base color `zinc`, CSS variables), `@tanstack/react-query` v5, Zustand, i18next/react-i18next, axios, Dexie (IndexedDB), lucide-react, Vitest. Path alias `@/` → `src/`.

## 1. Naming

| Where | Convention | Example |
|---|---|---|
| Components in `src/domains/**/components/` | **kebab-case** file names | `domains/chat/components/message-item.tsx` |
| Route/layout components in `src/pages/` | **PascalCase** file names | `pages/AppPage.tsx`, `pages/LoginPage.tsx` |
| API modules | **dot-suffixed** `<domain>.api.ts` | `domains/auth/api/auth.api.ts`, `channels.api.ts` |
| React Query hooks | `use-<thing>.ts` file, `use<Verb><Thing>` export | `use-get-channels.ts` → `useGetChannels` |
| Zod schemas | `<thing>.schema.ts` | `domains/auth/validation/login.schema.ts` |
| Types | `<domain>.types.ts` | `domains/channels/types/channels.types.ts` |
| Zustand stores | `<name>.store.ts` / existing `*.slice.ts` | `domains/voice/store/voice.store.ts` |
| Shadcn primitives | whatever the Shadcn CLI generates (kebab-case) | `components/ui/dropdown-menu.tsx` |

Exported component identifiers are always PascalCase regardless of file name.

## 2. Folder structure (Feature-Sliced / DDD)

Target layout. **Only create folders you actually need** — no empty `types/` or `validation/` folders "for later".

```
client-web/
├── components.json              # Shadcn config
├── src/
│   ├── app/                     # Layer 1: app-wide setup — providers (QueryClient, i18n, theme, ErrorBoundary), router, global store wiring, index.css
│   ├── components/              # Layer 2: shared/atomic UI
│   │   └── ui/                  #   Shadcn primitives (generated by the CLI — edit sparingly)
│   ├── hooks/                   # Layer 3: generic hooks (use-media-query, use-debounce, use-toast)
│   ├── lib/                     # Layer 4: global utilities — cn(), api client (axios instance + APIError), logger, db (Dexie), crypto helpers, formatters
│   ├── i18n/                    # i18next setup + locales/{en,fa,ar}.json
│   ├── ws/                      # WebSocket transport (socketManager, shared worker)
│   ├── domains/                 # Layer 5: business domains
│   │   └── <domain>/            #   auth, channels, messages, files, users, relationships, voice, whisper, settings
│   │       ├── api/             #   <domain>.api.ts (axios calls) + React Query hooks
│   │       ├── components/      #   domain UI (kebab-case files)
│   │       ├── hooks/           #   domain business logic hooks
│   │       ├── store/           #   domain Zustand slice, if any
│   │       ├── types/           #   DTOs & interfaces
│   │       ├── utils/           #   pure domain helpers
│   │       └── validation/      #   zod schemas
│   └── pages/                   # Layer 6: route & layout composition only (PascalCase)
├── tailwind.config.js
├── vite.config.ts
└── tsconfig.json
```

Layer rules:
- A layer may import only from layers **below** it (`pages` → `domains` → `lib`/`hooks`/`components` → nothing app-specific). `components/ui` must not import from `domains`.
- Domains should not reach into each other's internals; if two domains share something, move it down to `lib/`, `hooks/`, or `components/`.
- `pages/` only composes domain components and handles routing — no business logic, no direct API calls.

**Migration (the repo is mid-transition):** current code lives in flat `src/api/client.ts`, `src/components/**`, `src/hooks/use*.ts`, `src/store/*`, `src/types/api.ts`, `src/utils/*`. New features go straight into `src/domains/<domain>/`. When you substantially modify an existing file, move it into its domain as part of that change (update imports, keep tests passing). Don't do drive-by bulk moves outside the task.

## 3. UI & styling

- **Shadcn first.** Add primitives with `pnpm dlx shadcn@latest add <component>` (run from `client-web/`). Never hand-roll a button, dialog, dropdown, tooltip, sheet, input, etc. if Shadcn has one. Existing primitives live in `src/components/ui/`.
- **Aesthetic:** Discord-inspired — flat, simple, dense but readable. No heavy drop shadows, gradients, or glassmorphism. Prefer borders/`bg-muted` separation over elevation.
- **Colors:** use only the theme tokens (`bg-background`, `text-foreground`, `bg-primary`, `text-muted-foreground`, `bg-accent`, `border-border`, `bg-destructive`, …). **No hard-coded hex/rgb/hsl and no raw Tailwind palette colors** (`bg-zinc-800`, `text-blue-500`) in components. If a new semantic color is needed, add a CSS variable in `src/index.css` for both `:root` and `.dark`, and map it in `tailwind.config.js`.
- **Light + dark** must both look correct for every change.
- **Icons:** `lucide-react` only.
- **Motion:** `framer-motion` is available; keep animations subtle and short.

## 4. i18n & directionality

- **No hard-coded user-facing strings.** Every label, placeholder, aria-label, title, toast, and empty state uses `t('…')` from `react-i18next`.
- Add every new key to **all three** files: `src/i18n/locales/en.json`, `fa.json`, `ar.json` (provide a real translation, not English copy). `src/i18n/locales.test.ts` fails on missing keys.
- Group keys by domain (`channels.create.title`, `auth.login.submit`).
- **Design RTL-first, LTR-compatible.** Arabic (`ar`) renders RTL via `RTL_LANGUAGES` in `src/i18n/index.ts`. Note: per product decision **Farsi (`fa`) currently stays LTR** (text swaps only) — don't change that without being asked, but code must still work if it flips.
- **Use logical Tailwind classes only**, never physical ones:

  | ❌ Physical | ✅ Logical |
  |---|---|
  | `ml-*` / `mr-*` | `ms-*` / `me-*` |
  | `pl-*` / `pr-*` | `ps-*` / `pe-*` |
  | `left-*` / `right-*` | `start-*` / `end-*` |
  | `text-left` / `text-right` | `text-start` / `text-end` |
  | `border-l` / `border-r` | `border-s` / `border-e` |
  | `rounded-l-*` / `rounded-r-*` | `rounded-s-*` / `rounded-e-*` |

  Directional icons (chevrons, arrows, "back") need `rtl:rotate-180` / `rtl:-scale-x-100`. When you touch a file that still uses physical classes, convert them.

## 5. State & data fetching

- **Server state = `@tanstack/react-query` only.** Never store server data in `useState` + `useEffect` fetches, or duplicate it in Zustand. Zustand is for client/UI state (auth session flags, active channel, voice/whisper session state, WS connection).
- **Layering:** `<domain>.api.ts` holds plain typed functions calling the shared axios client (`apiClient` + the `request<T>()` helper). Components never call axios directly — they use a custom hook (`useGetChannels`, `useUpdateProfile`, `useSendFriendRequest`).
- **Query keys:** hierarchical arrays starting with the domain (`['channels', id, 'members']`). Export a key factory per domain when a domain has more than a couple of keys, and use it for invalidation.
- **Real-time:** WebSocket events update the React Query cache (`queryClient.setQueryData` / `invalidateQueries`) — don't build a parallel store.
- **Search before writing:** check `src/domains/*/api/`, `src/hooks/`, and `src/api/client.ts` for an existing function/hook first.
- **No mock data.** If the endpoint doesn't exist, stop and tell the user the backend route must be built first.
- **Debounce** every input that triggers a request (search boxes, availability checks, autosave) with a shared `useDebounce` hook in `src/hooks/` (create it once if missing; don't inline `setTimeout`s).

## 6. Feedback & errors (toasts)

- Use the Shadcn toast component (`sonner` via `pnpm dlx shadcn@latest add sonner`) for action feedback; there is no toast system yet — add it once, in `components/ui` + the provider in `app/`, then reuse it.
- **Prefer backend messages over hard-coded text.** The backend returns `{ "error": "<message>" }` on failure, which the axios interceptor exposes as `APIError.message`. Show that message in error toasts. For success, show the backend's `message` field when the response includes one; otherwise fall back to an i18n key. Never hard-code English strings in toasts.
- Handle `NetworkError` / `AuthError` from `@/api/client` (→ `lib/`) distinctly; 401s are already broadcast as `auth:unauthorized`.
- Use `logger` from `@/utils/logger` (→ `lib/logger`) instead of `console.*`.

## 7. Forms & validation

- **`zod` for all form validation** (add with `pnpm -C client-web add zod` when first needed), schemas in `domains/<domain>/validation/`. Infer form types from schemas (`z.infer<typeof schema>`) instead of writing them twice.
- Use **`@persian-tools/persian-tools`** for Persian-specific validation/formatting (digit conversion, phone numbers, national IDs, number words) instead of custom regex.
- Normalize Persian/Arabic digits to Latin before validating numeric input.
- Disable `autoComplete="off"` and `autoCapitalize="off"` (plus `autoCorrect="off"`, `spellCheck={false}` for identifiers) on most inputs. Keep autocomplete only where it clearly helps the user (`username`, `current-password`/`new-password` on auth forms, email).
- **Required fields: always append ` *` to the label** (render it via a shared label/required-marker component, not hand-typed per form).
- Validation error messages are i18n keys, not literal strings.

## 8. Modularity & types

- Keep components small and single-purpose. If a file passes ~250 lines or mixes data fetching, layout, and complex interaction, split it (container hook + presentational pieces). Several existing files (`ChatArea.tsx`, `SettingsModal.tsx`, `MessageItem.tsx`) are examples to split when touched.
- All API DTOs and shared interfaces live in `domains/<domain>/types/` (or `src/types/` for truly global types). Mirror backend JSON field names (`snake_case`) exactly in DTOs.
- Desktop compatibility: when code differs between browser and Wails, branch with `isWails()` from `@/utils/wails` in one place (usually `lib/`), not scattered through components.
