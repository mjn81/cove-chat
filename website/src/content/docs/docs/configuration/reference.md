Copy `backend/config.toml.example` to `config.toml` next to the server binary (or mount it into the container). Keys not listed there use built-in defaults. Restart the server after editing the file unless the admin panel says the key applies live.

The `[server]` keys `min_client_version` and `enforce_min_client` control the minimum client check; see [Minimum client version](/docs/api/standard/#minimum-client-version). At the release that ships API version 2, set `min_client_version = "0.10.0"`.

## `[server]`

### `server.domain`

Default: `"localhost"`

The public domain name of this node. Used for inter-node federation.

### `server.http_port`

Default: `4000`

HTTP API and WebSocket port.

### `server.udp_port`

Default: `9090`

UDP port of the encrypted media router. Only used when [voice] mode = "raw_udp"
(air-gapped/LAN calls, native clients); nothing listens on it in the default "webrtc" mode.

### `server.frontend_origin`

Default: `"http://localhost:5173"`

The origin(s) allowed to access the API via CORS. Comma-separated.
Use "*" to allow all origins (not recommended for production).
Note: Wails desktop app origins are allowed by default.

### `server.max_file_size_mb`

Default: `100`

Maximum allowed file upload size in MB.

### `server.max_video_size_mb`

Default: `50`

Maximum allowed video message size in MB.

### `server.max_video_duration_sec`

Default: `60`

Maximum video message duration in seconds.

### `server.ffmpeg_path`

Default: `"ffmpeg"`

Path to ffmpeg binary (for video transcoding).

### `server.dev`

Default: `false`

Enable development mode (extra logging, Swagger UI at /api/docs/).

### `server.min_client_version`

Default: `""`

Oldest client app version (MAJOR.MINOR.PATCH) this server supports. Empty = no minimum.
Clients below it get an "out of date" banner (soft mode, see enforce_min_client).
API v2 changed every list endpoint to a paged {items, next_cursor} envelope, so at the release that ships it
set this to "0.10.0" so clients that predate it are told to update instead of misreading the lists.

### `server.enforce_min_client`

Default: `false`

false (default): warn only, old clients keep working as far as they can.
true: requests from clients below min_client_version (or sending no X-Cove-Client header) get HTTP 426 and the
client shows a blocking "update required" screen. /api/version, /api/server-info and /ws stay reachable.

## `[security]`

### `security.master_password`

Default: `""`

Master password for encrypting the database DEK via Argon2id (KEK derivation).
If left empty, the server will generate a secure 32-char random string on first
launch, print it to the terminal, and write it here automatically.
IMPORTANT: Back this up. Losing it makes the database unrecoverable.

### `security.token_expire_hours`

Default: `24`

Number of hours before the authentication token and session expire.

## `[database]`

### `database.path`

Default: `"./data/db"`

Path where BadgerDB stores its data files.

### `database.auto_repair`

Default: `true` (commented out in the example; optional)

On start-up, drop database table files that a power loss or killed process left filled with zeros, keep a copy of
the original, and message the admins, instead of refusing to start. Only what was stored in those files is lost.
Set to false to fail loudly and run "cove-server repair" yourself.

## `[voice]`

### `voice.mode`

Default: `"webrtc"`

Group audio/video calling + screen share engine.
    "webrtc"  - production, internet-capable: a self-hosted SFU (see
    internal/rtc) with encrypted media (DTLS-SRTP) and NAT
    traversal via ICE/STUN/TURN. Supports video + screen share.
    "raw_udp" - the encrypted UDP media router (internal/mediarouter,
    docs/udp-media.md) for isolated/LAN deployments where every
    client can already reach the server directly. Audio, video
    and screen share over AES-256-GCM; native clients only (the
    web client's call buttons are disabled in this mode).

### `voice.max_participants_per_call`

Default: `10`

Maximum participants in a single call (resource cap; enforced at join).

### `voice.webrtc_port_min`

Default: `50000`

WebRTC media (ICE/DTLS/SRTP) ephemeral UDP port range. Firewall this
range on the host; each active track negotiation uses one port.

### `voice.webrtc_port_max`

Default: `50100`

### `voice.public_ip`

Default: `"auto"`

Required whenever this process is behind NAT/a cloud load balancer/a
Docker port mapping — the IP clients should use to reach it. "webrtc" mode
is the internet-capable engine, so it's fine (and the default) for this to
assume internet access is available. Deployments with NO internet egress
at all should use mode = "raw_udp" above instead of "webrtc" with this
left empty.
    "auto"    - (default) auto-detect via a one-time STUN query at startup.
    Falls back to "" behavior if unreachable.
    ""        - direct/LAN-only "webrtc" deployments; never calls out.
    "1.2.3.4" - explicit manual value.

### `voice.public_ip_discovery_stun_servers`

Default: `["stun:stun.l.google.com:19302"]` (commented out in the example; optional)

Only used when public_ip = "auto"; overrides the default STUN servers.

### `voice.embedded_turn_enabled`

Default: `true`

Runs our own STUN+TURN relay in-process (github.com/pion/turn) so NAT
traversal works without any external TURN provider. Requires public_ip
to be set to be useful. Disable for LAN-only deployments that don't need
NAT traversal at all.

### `voice.embedded_turn_port`

Default: `3478`

### `voice.turn_realm`

Default: `"cove"`

### `voice.turn_shared_secret`

Default: `""`

Drives short-lived, per-call HMAC-derived TURN credentials (TURN REST API
convention) — never a static shared secret handed to clients directly.
Generated automatically on first run and persisted here, like
master_password above.

## `[registration]`

Who may create an account. Editable live from the admin panel; whatever you
set here is the starting value. The very first account on a fresh server is
always allowed - it becomes the server owner.

### `registration.mode`

Default: `"open"`

    "open"        anyone can sign up
    "invite_only" a valid invitation code is required
    "closed"      nobody can sign up

## `[admin]`

### `admin.owner_username`

Default: `""` (commented out in the example; optional)

Recovery for a lost owner login: set this to an existing username and restart
to make that account the owner (the previous owner becomes an admin).

## `[demo]`

Off by default. Turn on for a public demo instance: clients show a "data resets, not private" notice
and sign-ups are capped. The first account on a fresh server is exempt from the per-IP limit.

### `demo.enabled`

Default: `false` (commented out in the example; optional)

### `demo.max_users`

Default: `200` (commented out in the example; optional)

total accounts allowed; 0 = no cap

### `demo.signups_per_ip_per_day`

Default: `3` (commented out in the example; optional)

new accounts per client IP per rolling 24h; 0 = no cap

## `[captcha]`

A self-hosted proof-of-work check (ALTCHA): every Cove client solves a small puzzle automatically when
someone registers, so bulk sign-ups cost the attacker CPU time. No third-party service, no tracking.
Both keys can also be changed live from the admin panel. The very first account is always exempt.

### `captcha.enabled`

Default: `false` (commented out in the example; optional)

### `captcha.difficulty`

Default: `"medium"` (commented out in the example; optional)

low | medium | high (about 12k, 50k and 200k hashes on average)
