The server side of emoji styles, custom emoji, animated emoji and stickers. Everything here is **additive** to the
[API standard](/docs/api/standard/) (`api_version` is unchanged) and is advertised through capabilities, so old clients
ignore it and new clients can tell whether a server has it.

Swagger (`backend/docs/`) is the field-by-field reference; this page is the guide a client developer needs: what exists,
how to cache it, and which rules the server enforces.

## Capabilities

`GET /api/version` and the WebSocket `hello` list:

| Capability | Meaning |
|---|---|
| `emoji_packs` | `GET /api/emoji/styles` serves emoji styles (sprite sheets). |
| `custom_emoji` | `GET /api/emoji/custom` serves the server's custom emoji; `:name:` shortcodes work in text. |
| `stickers` | Sticker packs under `/api/packs` and the `sticker` message type. |
| `animated_emoji` | `GET /api/emoji/animated` serves the animated emoji table. |

## What a client needs before sign-in

`GET /api/server-info` (public) gained three fields so the login screen and first start can already pick a style:

```json
{ "emoji_styles": ["native", "noto", "twemoji"], "default_emoji_style": "noto", "user_stickers_enabled": true }
```

`emoji_styles` are the style ids users may choose, `default_emoji_style` is the one to start with (always one of them).
`native` is the device's own emoji font and has no assets. Everything else below needs a signed-in session
(cookie, or Bearer token on desktop and Android) like any other endpoint.

## Emoji styles

Built-in styles: **`noto`** (default), **`twemoji`**, **`blobmoji`**, **`fluent`** (Fluent Emoji Flat), **`fxemoji`**, plus
the client-only **`native`**. They are generated by `make emoji/build`, embedded in the server binary and need no internet
access at run time, so air-gapped servers work. The admin chooses which are offered and the default
(`emoji.enabled_styles`, `emoji.default_style` in `config.toml` or the admin panel; applied live).

`GET /api/emoji/styles` returns the enabled styles with their asset URLs:

```json
{
  "default_style": "noto",
  "enabled_styles": ["native", "noto", "twemoji"],
  "styles": [{
    "id": "noto", "name": "Noto Color Emoji", "license": "Apache-2.0", "version": "3fa9c1d2e4b7",
    "cell_size": 64, "width": 4096, "height": 3776, "count": 3750,
    "sheet_url": "/api/emoji/styles/noto/3fa9c1d2e4b7/sheet.webp",
    "index_url": "/api/emoji/styles/noto/3fa9c1d2e4b7/index.json",
    "sheet_bytes": 4552000, "index_bytes": 90000, "default": true
  }]
}
```

* **Sprite sheet** (`sheet.webp`): one WebP image, a grid of `cell_size` px (64) square cells, `width / cell_size` columns.
* **Index** (`index.json`): `{"size": 64, "width": 4096, "height": 3776, "emoji": {"1f600": [x, y], ...}}`. A key is the
  emoji's code points as lower-case hex joined by `-`, **with every FE0F (variation selector-16) removed**; the value is
  the top-left pixel of its cell (the cell is `size` x `size`). Build the key from a rendered emoji by dropping U+FE0F,
  hex-encoding the rest and joining with `-` (`❤️` → `2764`, `👍🏽` → `1f44d-1f3fd`, `🇩🇪` → `1f1e9-1f1ea`).
* **Coverage**: Noto and Twemoji cover about 3,750 to 4,000 sequences (skin tones, flags, ZWJ families); Blobmoji about 2,700;
  Fluent Flat about 1,600 (default skin tone only); FxEmojis about 1,000 (single code points only). **A sequence missing from the index is rendered
  with the device font** (the client always keeps the original character as alt text).
* **Caching**: both URLs contain `version`, a content hash, so they are immutable: `Cache-Control: private, max-age=31536000,
  immutable` plus an `ETag` (conditional requests answer 304). A new server release with changed art changes the version
  and therefore the URL. A style the admin has disabled, or a stale version, is `404`.
* **Client size policy**: bundle at most the default style in the app and download the others on demand from
  these URLs, then cache them (IndexedDB on web, app files on Android). `sheet_bytes` lets you show the download size.
* The list endpoint also has an `ETag` (`Cache-Control: private, no-cache`), so refreshing it on every start is one cheap
  conditional request.

### Real sizes

| Style | Emoji | Sheet |
|---|---|---|
| `noto` Noto Color Emoji (Apache-2.0) | 3,750 | 4.34 MB (index 108 KB) |
| `twemoji` Twemoji, jdecked fork (CC BY 4.0) | 4,009 | 4.57 MB (index 115 KB) |
| `blobmoji` Blobmoji (Apache-2.0) | 2,687 | 1.98 MB (index 69 KB) |
| `fluent` Fluent Emoji Flat (MIT) | 1,595 | 1.18 MB (index 32 KB) |
| `fxemoji` FxEmojis (CC BY 4.0) | 986 | 0.72 MB (index 18 KB) |

Together the five sheets are 12.8 MB. Cove Basics is 0.66 MB (48 stickers, the largest 24 KB) and Cove Moves 7.5 MB (72
animations, none over 150 KB); the whole `assets/` folder is 21.4 MB, which grows the server binary by about 22 MB
(Windows amd64, stripped: 31.5 MB to 54.6 MB). All assets are committed, so `go build` and `make test` need no network.
Their line endings are never converted (`.gitattributes`), because the content hash is part of every asset URL.

## Animated emoji (big single emoji)

`GET /api/emoji/animated` returns the table a client uses to show a message that is **exactly one emoji** as a big
animation (web, desktop and Android all follow the same rule):

```json
{ "version": "9a8b7c6d5e4f", "items": [
  { "sequence": "1f680", "id": "rocket", "url": "/api/emoji/animated/9a8b7c6d5e4f/rocket.webp" } ] }
```

`sequence` uses the same key rule as the style indexes (lower-case hex code points joined by `-`, FE0F removed). The
images are 256 px animated WebP (the "Cove Moves" animations, CC BY 4.0), immutable and versioned like the sheets. The
message stays plain Unicode on the wire; there is no new message type. A single emoji with no entry here, or two to three
emoji, is shown as a large static image of the active style; four or more are normal text.

## Custom emoji

The admin uploads emoji (`POST /api/admin/emoji`); users send them as **`:name:` inside ordinary text** (no message type).
`GET /api/emoji/custom` returns the set:

```json
{ "version": "v3", "items": [
  { "name": "party_parrot", "url": "/api/packs/custom-emoji/items/3f2a…/file", "file_id": "…", "animated": true,
    "width": 128, "height": 128 } ] }
```

* **Shortcode rule**: `[a-z0-9_]{2,32}`, lower case, unique on the server. The upload form accepts `:Name:` and
  normalises it. Tokenise text with `:([a-z0-9_]{2,32}):`; a name that is not in the list is shown as typed.
* **Images**: PNG, WebP or GIF, normalised to at most 128x128 and 256 KB (see [uploads](#uploads)). Immutable URLs.
* `version` changes whenever the set changes and the response carries an `ETag`; refresh at start and when a message uses an
  unknown `:name:`.

## Sticker packs

A pack has `id`, `kind` (`sticker`), `scope`, `name`, `version`, license/attribution, `enabled`, `default`, `order`.

| Scope | Where it lives | Who sees it |
|---|---|---|
| `builtin` | embedded in the binary (ids `cove-basics`, `cove-moves`) | everyone, while enabled |
| `server` | database, managed by admins | everyone, while enabled |
| `user` | database, owned by one user | the owner and users who added it |

**Cove Basics**: 48 static stickers (Fluent Emoji 3D, MIT), 512 px WebP. **Cove Moves**: 72 animated stickers (Noto Emoji
animations, CC BY 4.0), 256 px animated WebP. The admin can enable, disable, reorder and set the default pack, and can add
server packs of their own.

### Endpoints (all authenticated; `protect`)

| Method and path | Purpose |
|---|---|
| `GET /api/packs` | The caller's picker: enabled built-in and server packs plus owned or added user packs, default pack first. No items (use `item_count`, `cover_url`). Includes `quota`. |
| `GET /api/packs/{id}` | One pack with `items`. Built-in, server (while enabled) or any user pack (the unguessable id is the share link). |
| `PUT /api/packs/{id}/install` | Add a user pack to the caller's picker (share card "Add"). Idempotent. 400 for built-in and server packs. |
| `DELETE /api/packs/{id}/install` | Remove it again. 400 for your own pack (delete it instead). |
| `POST /api/packs` | Create a user pack `{name, description?}`. |
| `PATCH /api/packs/{id}` | Rename (owner). |
| `DELETE /api/packs/{id}` | Delete with all stickers and stored images (owner). |
| `POST /api/packs/{id}/items` | Upload a sticker (multipart `file`, optional `emoji`). Owner. |
| `DELETE /api/packs/{id}/items/{item}` | Remove a sticker (owner). |
| `PUT /api/packs/{id}/order` | `{item_ids: [...]}` every id exactly once (owner). |
| `GET /api/packs/{id}/items/{item}/file` | A stored sticker or custom emoji image (immutable, `ETag`). |
| `GET /api/stickers/builtin/{pack}/{version}/{file}` | A built-in sticker (`<id>.webp`), immutable. |
| `GET /api/packs/attribution` | Credits for every shipped art set (for the About page). |

Item DTO: `{id, name?, emoji?, animated, url, file_id?, width?, height?, bytes, order}`. Use `url` as is (relative to the API
base). `file_id` is the stored image of a server or user sticker and is what a sticker message carries; built-in stickers
have none. A `PackResponse` also has `installed`, `editable`, `owner_id`/`owner_name` (user packs) and `version`
(`v<n>` for stored packs, a content hash for built-in ones; it changes whenever the contents change).

Admin management (`protectAdmin`; owner counts as admin):

| Method and path | Purpose |
|---|---|
| `GET /api/admin/packs` | Every pack on the server (built-in, server, all user packs) for management and moderation. |
| `POST /api/admin/packs` | Create a server pack. |
| `PATCH /api/admin/packs/{id}` | Server packs: `name`, `description`, `enabled`, `default`, `order`. Built-in packs: `enabled`, `default`, `order`. User packs: `name`, `description` only. Only one pack is ever the default. |
| `DELETE /api/admin/packs/{id}` | Remove any server or user pack (audited as `pack.delete` with the owner). Built-in packs are disabled instead. |
| `POST /api/admin/packs/{id}/items`, `DELETE …/items/{item}`, `PUT …/order` | Same as the user routes, on any stored pack, without user quotas. |
| `POST /api/admin/emoji` | Add a custom emoji (multipart `name`, `file`). |
| `DELETE /api/admin/emoji/{name}` | Remove one. |

Every admin pack change is written to the audit log (`pack.create`, `pack.update`, `pack.delete`, `pack.item.add`,
`pack.item.delete`, `pack.reorder`, `emoji.add`, `emoji.delete`).

## Uploads

Uploading is multipart with a `file` part. Rules, in order:

1. At most 4 MB is read at all (`413 payload_too_large` above that).
2. The type is decided by **magic bytes**: PNG, JPEG, GIF or WebP for stickers; PNG, GIF or WebP for custom emoji.
   **SVG and everything else is refused** (`400 image_invalid`), whatever the file name or the claimed content type says.
3. A source side over 4096 px is refused before any decoding (decompression-bomb guard).
4. **Normalisation**. With `ffmpeg` available (`server.ffmpeg_path`) the image is re-encoded as WebP no larger than the cap
   (512x512 for stickers, 128x128 for custom emoji), which also strips metadata; animations stay animated (at most 10 s).
   Without ffmpeg, or when ffmpeg cannot read the file (for example an animated WebP), the **strict fallback** stores the
   original bytes only if they already fit the caps; otherwise `400 image_invalid` (too many pixels) or `413` (too many
   bytes). Result caps: stickers 512 KB, custom emoji 256 KB.
5. At most four images are normalised at the same time; a busy server answers `503 service_unavailable`.

### Limits and the admin switch (user packs only)

| Setting (`config.toml`, admin panel) | Default | Meaning |
|---|---|---|
| `packs.user_uploads_enabled` | `true` | Off: users cannot create packs or upload (`403 pack_uploads_disabled`). Existing packs keep working and can be deleted. |
| `packs.max_packs_per_user` | 10 | `409 pack_limit_reached` beyond this. |
| `packs.max_stickers_per_pack` | 60 | `409 pack_limit_reached`. |
| `packs.max_user_storage_mb` | 20 | Total size of all of a user's stickers; `409 pack_limit_reached`. |

`GET /api/packs` returns the caller's `quota` (limits, current usage and the per-image caps). Server packs and custom emoji
are not subject to these quotas. Deleting a pack or a sticker deletes the stored image; deleting an account deletes its
packs and images.

### Privacy trade-off

Sticker and custom emoji images are **not encrypted and not tied to a channel**. Like avatars they are channel-less files
readable by any signed-in user who knows the unguessable ids (`GET /api/files/{id}` and the item file route). That is what
lets one stored image show in every conversation without re-encrypting it per channel. The *message* that references a
sticker is encrypted like any other; only the image itself is shared. Do not put anything private in a sticker.

## The `sticker` message

New message `type`: `sticker` (`models.MessageTypeSticker`; listed in [API standard](/docs/api/standard/) section 5). The body is
encrypted like any message and decrypts to JSON:

```json
{ "pack_id": "cove-basics", "sticker_id": "rocket", "file_id": "" }
```

The server decrypts it (server-trusted model) and rejects the message with a `message_error` event, code
`sticker_invalid`, unless:

* `pack_id` and `sticker_id` are present (each at most 128 characters) and `compression` is `none`;
* **built-in pack**: it is enabled, holds `sticker_id`, and `file_id` is empty or equals `sticker_id`;
* **server or user pack**: it exists, is a sticker pack (a server pack must be enabled), holds `sticker_id`, and `file_id`
  is that sticker's stored image (`file_id` from the item DTO).

Any user pack that exists may be used by any member who has its id: the id is as unguessable as a file id, and this keeps
**forwarding** a received sticker working without installing the pack first. Sticker messages cannot be edited. The sender
must be an active member of the channel, as for every message. Render by `pack_id`/`sticker_id`: built-in →
`/api/stickers/builtin/{pack}/{version}/{id}.webp` (version from the pack detail), stored → the item `url`. A client that does
not know the type shows the generic placeholder for unknown message types.

## Error codes

Added to `internal/apistd` (stable; the message text is for humans):

| Code | Status | When |
|---|---|---|
| `pack_not_found` | 404 | Pack, item or custom emoji does not exist or is not visible. |
| `pack_limit_reached` | 409 | Packs per user, stickers per pack or total storage quota reached. |
| `emoji_name_taken` | 409 | Another custom emoji uses the shortcode. |
| `pack_uploads_disabled` | 403 | The admin switched user uploads off. |
| `image_invalid` | 400 | Not a PNG/JPEG/GIF/WebP, or too many pixels. |
| `sticker_invalid` | (WebSocket `message_error`) | A sticker message does not match its pack. |

Plus the generic `unauthorized` (401), `forbidden` (403, for example editing someone else's pack),
`validation_failed` (400), `payload_too_large` (413), `rate_limited` (429) and `service_unavailable` (503).

## Building the assets

`make emoji/build` regenerates `backend/internal/packs/assets/` (sprite sheets, indexes, sticker WebP files, licence texts,
`ATTRIBUTION.md`, `manifest.json`) with `scripts/emoji/build.mjs`. It needs Git, network access (upstream repos are
sparse-cloned into `scripts/emoji/.cache/`), Node 20+ and `pnpm install` in `scripts/emoji/` (the `sharp` library bundles
libwebp and librsvg, so no ffmpeg, cwebp or ImageMagick is needed). Upstream sources: `googlefonts/noto-emoji`,
`jdecked/twemoji`, `C1710/blobmoji`, `microsoft/fluentui-emoji`, `mozilla/fxemoji`, and the Noto animated emoji from
`fonts.gstatic.com`. OpenMoji is not included.
